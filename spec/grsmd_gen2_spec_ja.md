## 1. 基盤

### 1.1 背景

開発者やテクニカルライターは、作業中にMarkdown、Mermaidダイアグラム、PlantUML、LaTeX数式のプレビューを頻繁に必要とする。既存のオンラインツールは大きく2つに分類される:

- **サーバーサイドレンダラー**（例: HackMD、StackEdit）: アカウント作成が必要で、ユーザーコンテンツを外部サーバーに送信する。機密文書には不適。
- **デスクトップアプリケーション**（例: Typora、VS Code拡張機能）: インストールと設定が必要。共有マシンやロックダウンされたマシンでは常に利用可能とは限らない。

ブラウザ上で完全に動作し、インストール不要で、ユーザーが明示的にオプトインしない限りコンテンツがデバイス外に出ないツールには、依然としてギャップがある。

加えて、Markdownドキュメントと並行してソースコードをレビューする開発者には、ツールを切り替えることなくシンタックスハイライト付きでコードを閲覧できる軽量な手段が必要である。キーボード駆動のナビゲーションも、効率的なコードレビューとドキュメント閲覧に不可欠である。

### 1.2 課題

| ID     | 課題                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------ |
| ISS-01 | オンラインMarkdownレンダラーはユーザーコンテンツをサーバーに送信するため、機密文書のプライバシー要件に違反する。   |
| ISS-02 | デスクトップツールはインストールと設定が必要であり、共有マシンや制限されたマシンでは障壁となる。                   |
| ISS-03 | 多くのMarkdownプレビューアはMermaid、PlantUML、LaTeX数式を同時にサポートしていない。                               |
| ISS-04 | PlantUMLは仕様上サーバーレンダリングが必要だが、ほとんどのツールはユーザーに外部通信の事実を通知しない。           |
| ISS-05 | Markdownと並行して、行番号付きのシンタックスハイライト済みソースコードを表示できる軽量ブラウザツールが存在しない。 |
| ISS-06 | キーボード駆動のワークフローへの対応が不十分。スクロールやテーマ切替にマウスが必須となっている。                   |
| ISS-07 | .txtファイルが以前はMarkdownとして扱われていたが、プレーンテキストやログファイルとしては不正確である。             |

### 1.3 目標

| ID   | 目標                                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------------------------- |
| G-01 | **プライバシー優先**: ユーザーの明示的同意なしに、一切のデータを外部に送信しない。                                   |
| G-02 | **即時性**: ペーストまたはドロップから数秒以内にプレビューを表示する。                                               |
| G-03 | **ゼロインストール**: ブラウザを開くだけで利用可能。サーバー不要、プラグイン不要。                                   |
| G-04 | **単一ファイル配布**: 単一HTMLファイルで全機能を提供する。                                                           |
| G-05 | **マルチフォーマット**: Markdown、Mermaid、PlantUML、LaTeX (KaTeX)、シンタックスハイライトを統一的にサポートする。   |
| G-06 | **Quick Code View**: 非.mdファイルに対し、行番号付きシンタックスハイライト対応コードビューを提供する。               |
| G-07 | **キーボードナビゲーション**: スムーススクロール（矢印キー）とショートカット（l/d/n/c）を両ビューで提供する。        |
| G-08 | **テーマ**: OS自動検出付きのライト/ダークテーマをサポートする。                                                      |
| G-09 | **ライブリロード**: FileSystemFileHandle 経由でファイルシステムからソースファイルをリロードする（Chrome/Edge 86+）。 |
| G-10 | **その場編集**: 編集モードの間、プレビュー上でブロック単位に Markdown の原文を直し、明示的に保存できる。画面の切り替えや分割は行わない。 |

### 1.4 解決方針

**ランタイムスタック:**

| レイヤー               | 技術                                                 | 備考                                             |
| ---------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| 言語                   | JavaScript (ES6+ クラス)                             | 当面TypeScriptは使用しない                       |
| ランタイム             | ブラウザのみ（クライアントサイド SPA）               | バックエンドなし、Node.jsなし                    |
| Markdownパーサー       | marked.js v18.1.0 (UMD, バンドル)                    | ビルドに内包                                     |
| ダイアグラム描画       | Mermaid.js v11.17.2 (バンドル)                       | クライアントサイドのみ                           |
| PlantUMLエンコード     | plantuml-encoder v1.4.0 (バンドル)                   | エンコードのみ。描画は同意付き外部サーバー       |
| シンタックスハイライト | highlight.js v11.12.0 (バンドル)                     | Markdownコードブロックとコードビューの両方で使用 |
| 数式描画               | KaTeX v0.18.11 + marked-katex-extension v5.1.13 (バンドル) | LaTeX数式サポート                            |
| HTMLサニタイズ         | DOMPurify v3.4.16 (バンドル)                         | Markdown出力をDOM挿入前に必ずサニタイズ (OS-14)  |

**ビルド戦略:**

| レイヤー       | 技術                               | 備考                                               |
| -------------- | ---------------------------------- | -------------------------------------------------- |
| 開発ビルド     | Vite + vite-plugin-singlefile      | マルチファイル開発、単一ファイルリリース           |
| リリース成果物 | 単一HTMLファイル (docs/index.html) | CSS/JSはvite-plugin-singlefileでインライン化       |
| ライブラリ取込 | npm依存をViteでバンドル            | 全描画ライブラリを単一ファイルに内包 (実行時CDNなし) |
| ホスティング   | GitHub Pages                       | https://goodrelax.github.io/gr-simple-md-renderer/ |

**アーキテクチャ:** ES6クラスベースのSPA。Rendererパターン + Orchestratorによる協調制御。本番ではすべてのクラス、設定、スタイル、HTMLを単一ファイルに統合する。開発時はViteのマルチファイルソースを使用する。

- GitHub Pages のソースディレクトリは `docs/` に設定する（URL変更なし）。
- `sample-data.*` は `docs/` に配置する。ヘルプモーダル内のリンクが相対パスで参照するため。

注: `documentReplaced` / `documentCleared` は、INV-21 の確認で OK が選ばれた後にだけ起きる。`fullRenderRequested` は未保存の確認を出さない (INV-45)。`#editor` が空で本文が空でない場合は、INV-56 の確認で OK が選ばれた後にだけ `fullRenderRequested` が起きる (Cancel なら出来事は起きない)。`renderFromEditor` も、INV-56 の確認で Cancel なら `#editor` を本文に戻すだけで、全体描画もトーストも行わない (editModeIdle のまま)。編集欄を開いたまま、Shift+Tab などでフォーカスを編集欄の外 (本体) へ移した場合も、キーは document に届く。そのときの `l` / `d` / [Render] (キーボードでの押下を含む) は `fullRenderRequested`、`e` は `paletteHidden`、`r` / `c` / ドロップは INV-21 の確認を経て `documentReplaced` / `documentCleared` / `viewSwitchedToCode` になる (裁定 T1)。本体にフォーカスがある間の Esc は、5.11 の「ブロック編集中」の列のとおり `escapePressed` (編集の取消) になる。`#editor` にフォーカスが入ると `editorFocused` で確定する (裁定 T19)。`emptyDocumentStarted` は INV-31。`blockTapped` と `blockTappedWithUnrenderedEditor` は、開始ジェスチャ (INV-29) の時点で `_editorChangedSinceRender` が偽か真かで分かれる。`pointerPressedOutside` は、マウスでは `pointerdown`、タッチとペンでは移動の少ない `pointerup` で起きる (INV-30)。Undo は UIController が RendererOrchestrator に直接頼むので、この状態機械を動かさない (ブロック編集中は Undo ボタンが無効)。`#editor` に未描画の変更があるときの Undo と挿入は、INV-45 により `fullRenderRequested` と同じ全体描画 (editModeIdle の自己遷移) になる。`commitBlock` は同期でモデルを更新する (INV-47)。

通知の契約: 編集欄を閉じる処理 (`commitBlock`、`restoreOriginalRaw`、`discardBlockEditor`) は、`dispatch` の処理の途中で `BlockEditHost.onEditStateChanged()` と、確定でモデルが変わった場合の `onModelChanged` を呼ぶ。これらの通知は、`blockEditState` を表の次の状態に更新する **前** に出る。通知の受け手は `blockEditState` を読まず、編集欄が開いているかどうか (`isEditing()`。編集欄を閉じた時点で偽になる) だけを読むこと。

実装では、この表を `blockEditStateMachine` というデータとして持ち、出来事の入口 (`BlockEditController.dispatch`) が表を引いて動く。表の `enqueueFullRender` は、`dispatch` が戻った後で呼び出し側 (UIController) が行い、`showToast` は `renderFromEditor` に含まれる。`emptyDocumentStarted` は、全体描画が終わるまで editModeIdle に留まり、空の最初のブロックの編集欄を開いた時点で editingBlock になる。UI から到達しない交点 (例: editModeIdle × emptyDocumentStarted) も、`dispatch` を直接呼べば表のとおりに動く。

**11-e 保存処理の状態機械**

「未保存」は状態機械ではなく **導出値** とする (用語集。`UIController._isDocumentDirty()` = `session.isBodyChanged(orchestrator.getBody()) || blockEdit.hasUncommittedChange() || this._editorChangedSinceRender`)。状態変数を持たないので、未保存の印は「本文または編集欄が変わりうる時点」(確定、Undo、挿入、編集欄の `input`、`#editor` の `input`、全体描画、読み込み、保存の成功) で再計算する (INV-50)。

保存の処理中かどうかだけを状態機械にする。定義の名前は `saveOperationStateMachine`、今の状態を持つ変数は `saveOperationState` (`UIController` が持つ)。

**Save operation state machine:**

```mermaid
stateDiagram-v2
    [*] --> idle : appStarted
    idle --> writingFile : saveRequested
    idle --> writingFile : saveAsRequested
    writingFile --> idle : fileWritten
    writingFile --> idle : downloadStarted
    writingFile --> idle : writeFailed
    writingFile --> idle : saveCanceled
    writingFile --> writingFile : replaceRequested
```

| 出来事 \ 今の状態 | idle | writingFile |
| --- | --- | --- |
| saveRequested | → writingFile / startPermissionRequest, commitOpenBlock, applyEditorText, runSaveDocument | — (無視する。二重保存の防止) |
| saveAsRequested | → writingFile / startSavePicker, commitOpenBlock, applyEditorText, runSaveDocumentAs | — (無視する) |
| fileWritten | — | → idle / applyOutcomeIfSameDocument, refreshDirtyMark, showSavedToast (トーストは文書 ID によらず出す) |
| downloadStarted | — | → idle / showDownloadStartedToast (基準は更新しない。INV-26) |
| writeFailed | — | → idle / showErrorToast |
| saveCanceled | — | → idle |
| replaceRequested (5.14.11 で文書を作り直す出来事。テーマの切り替えは含まない) | — (この状態機械は関与しない。INV-21 / INV-55 で処理する) | → writingFile / rejectReplace, showSavingToast (INV-54) |

`saveRequested` / `saveAsRequested` は、`#editor` を取り込む場合 (`applyEditorText` が要る場合) に INV-56 の確認が要るなら、OK が選ばれた後にだけ起きる (Cancel なら `#editor` を本文に戻すだけで idle のまま、権限の要求も保存ダイアログも始めない。確認は同期なので、(1) の開始は最初の `await` より前のままである。INV-33)。writingFile の間の押下は、確認を出さずに無視する。`applyOutcomeIfSameDocument` は、`SaveOutcome.documentId` が現在の `DocumentSession.documentId` と一致するときだけ、セッションと保存先を置き換え、未保存の印を再計算する (INV-54)。保存のトースト (`messages.edit.saved`) は、別の文書の結果でも出す。ファイルは実際に書かれたので、それを知らせない方が利用者を惑わせるためである。実装では、この表を `saveOperationStateMachine` というデータとして持つ。

DiagramPanControllerは純粋なPC環境（fineポインターあり、かつcoarseポインターなし）でのみインスタンス化される。ハイブリッドデバイス（例: Surface）ではドキュメントスクロールとの競合を避けるためパンは無効化される。

**編集機能 (SC-22〜24) は全デバイスで有効。** 物理キーボードのないタッチ端末では、上部バーの [Edit] ボタン (`editBtn`) で編集モードに入る。パレットのジェスチャは Pointer Events で判定し、マウスとタッチで挙動を同じにする (INV-34 / INV-35)。タッチ端末では、空の初期状態でのダブルタップを `pointerup` 2 回の間隔と距離 (`CONFIG.edit.doubleTapMaxIntervalMs` / `doubleTapMaxDistancePx`) で判定する (INV-31)。プレビューには `touch-action: manipulation` を、パレットには `touch-action: none` を指定する **[要検証: iOS Safari]**。編集モードでは、図のブロックのクリックはコードを開く (図のダブルクリックによるズーム解除は、編集モードでない間に使う)。ドラッグによるパン (純粋な PC) は移動量が閾値を超えるので、編集の開始ジェスチャにはならない (INV-29)。上書き保存は Chrome / Edge のみで、そのほかはダウンロードにフォールバックする (INV-26)。

**実装方針 (v5: click-only + whitespace padding approach):**

iOS Safari はレンダリングされたコンテンツのない空白領域で click/touch イベントを発火しない。
`background-color` や `::after` 疑似要素では不十分であり、`<meta name="viewport">` の追加は既存レイアウトを破壊する。

対策:
1. `#affordanceText` を通常フロー配置（`padding-top: 40px` で上部寄せ）
2. アフォーダンステキストの後に空白行（`" \n"` x 50行）を付加し、プレビュー領域全体にレンダリング済みコンテンツを充填
3. `#preview` に `background-color` を明示指定（安全マージン）
4. `UIController.setupTouchPasteAssist()` で `click` イベントのみ監視
5. プレレンダー状態かつエディタ空の場合のみ `editor.focus()` を呼ぶ
6. `<meta name="viewport">` は追加しない（iPhone レイアウト崩壊の原因となるため）
7. `touchstart` は使用しない（ピンチアウト操作を阻害するため）

```javascript
document.addEventListener("drop", async (e) => {
  e.preventDefault();
  const item = e.dataTransfer.items?.[0];

  // Synchronous call before any await (CON-01)
  const handlePromise = FILE_SYSTEM_HANDLE_SUPPORTED
    ? item?.getAsFileSystemHandle?.()
    : null;

  const file = e.dataTransfer.files[0];
  if (!file) return;
  if (file.size > CONFIG.fileDrop.maxBytes) {
    alert(CONFIG.fileDrop.messages.tooLarge);
    return;
  }

  const ext = file.name.includes(".")
    ? file.name.slice(file.name.lastIndexOf(".")).toLowerCase()
    : "";

  if (CONFIG.fileDrop.markdownExtensions.includes(ext)) {
    // (1) .md -> Markdown Preview (with preprocessInput)
    const fileHandle = handlePromise ? await handlePromise : null;
    const text = this.preprocessInput(await file.text());
    this.elements.editor.value = text;
    await orchestrator.loadMarkdown(text, systemTheme(), fileHandle);
  } else if (EXT_TO_HLJS[ext] || EXT_TO_HLJS[file.name]) {
    // (2) Known text extension -> Code View (highlight attempt)
    this.elements.editor.value = ""; // RTC2-07: clear editor before code view
    const fileHandle = handlePromise ? await handlePromise : null;
    const metadata = await orchestrator.renderCodeView(file, fileHandle);
    this.setViewMode("code", metadata);
    this.showKeyHint("code");
  } else if (BINARY_EXTENSIONS.has(ext)) {
    // (3) Known binary extension -> reject
    alert(CONFIG.fileDrop.messages.binaryFile);
  } else {
    // (4)/(5) Unknown extension -> null byte check on first 8KB
    const slice = file.slice(0, 8192);
    const bytes = new Uint8Array(await slice.arrayBuffer());
    if (bytes.some((b) => b === 0)) {
      alert(CONFIG.fileDrop.messages.binaryFile);
      return;
    }
    // Text file with unknown extension -> Code View (plaintext)
    this.elements.editor.value = ""; // RTC2-07: clear editor before code view
    const fileHandle = handlePromise ? await handlePromise : null;
    const metadata = await orchestrator.renderCodeView(file, fileHandle);
    this.setViewMode("code", metadata);
    this.showKeyHint("code");
  }
});
```

### 5.6 SmoothScrollEngine

**クラススケルトン:**

```javascript
class SmoothScrollEngine {
  /**
   * @param {object} config - CONFIG.scroll reference
   * @param {HTMLElement} [scrollTarget] - element to scroll (defaults to window)
   */
  constructor(config, scrollTarget) {
    this._cfg = config;
    this._scrollTarget = scrollTarget || null;
    this._velocity = 0;
    this._direction = 0; // +1: down, -1: up
    this._keyHeld = false;
    this._rafId = null;
    this._lastTs = null;
    this._loop = this._loop.bind(this);
  }

  startScroll(direction) {
    this._direction = direction;
    this._keyHeld = true;
    // Suppress hover highlight during scroll (INV-18b)
    if (this._scrollTarget) this._scrollTarget.classList.add("scrolling");
    if (!this._rafId) {
      this._lastTs = null;
      this._rafId = requestAnimationFrame(this._loop);
    }
  }

  stopScroll() {
    this._keyHeld = false;
  }

  destroy() {
    if (this._rafId) cancelAnimationFrame(this._rafId);
    this._rafId = null;
    this._velocity = 0;
    this._lastTs = null;
    // Remove scrolling class (INV-18b)
    if (this._scrollTarget) this._scrollTarget.classList.remove("scrolling");
  }

  _loop(ts) {
    if (this._lastTs !== null) {
      const dt = Math.min(ts - this._lastTs, 50);
      if (this._keyHeld) {
        this._velocity = Math.min(
          this._velocity + this._cfg.acceleration * dt,
          this._cfg.maxSpeed,
        );
      } else {
        this._velocity *= Math.pow(this._cfg.friction, dt / 16.67);
      }
      if (this._velocity > 0.005) {
        const target = this._scrollTarget || window;
        target.scrollBy(0, this._direction * this._velocity * dt);
      } else {
        this._velocity = 0;
        this._rafId = null;
        this._lastTs = null;
        // Remove scrolling class when animation stops (INV-18b)
        if (this._scrollTarget)
          this._scrollTarget.classList.remove("scrolling");
        return;
      }
    }
    this._lastTs = ts;
    this._rafId = requestAnimationFrame(this._loop);
  }
}
```

**物理モデル概要:**

| フェーズ   | 計算式                                                   |
| ---------- | -------------------------------------------------------- |
| キー押下中 | `velocity = min(velocity + acceleration * dt, maxSpeed)` |
| キー解放後 | `velocity = velocity * pow(friction, dt / 16.67)`        |
| 停止条件   | `velocity < 0.005` px/ms: rAFループをキャンセル          |

- `dt` (デルタタイム、ミリ秒): 連続するrequestAnimationFrameコールバック間の経過時間。フレームレートに依存しないアニメーションに使用する。
- `dt` は50msで上限クランプ。タブ切替やスリープ後のジャンプを防止する。
- 摩擦は `Math.pow(friction, dt / 16.67)` により60fpsベースラインに正規化される。
- 物理パラメータ (maxSpeed, acceleration, friction) は `poc/smooth-scroll-poc.html` で実機テスト済みの値。すべて CONFIG 経由で調整可能。

### 5.7 ビュー状態管理

既存の `isPreRenderState()` はDOMを直接検査する (`children.length === 0`)。`#affordanceText` が `#preview` の永続的な子要素として追加されるため、この方式は破綻する。フラグベースのアプローチへの移行が必要。

`_viewState === 'markdown'` の中には、ブロック編集の状態 (`blockEditState`: `browsingPreview` / `editModeIdle` / `editingBlock`。3.3 の 11-c) がある。`_viewState` の値は増やさない。

`#editor` (上部の入力欄) はペーストの入口として残す。`#editor` と文書は次の規則で同期する: (1) ブロックの確定・Undo・挿入では、その操作のイベントハンドラの中で同期的にモデルを更新し、`onModelChanged` で UIController が `#editor.value` を本文で書き換え、`_editorChangedSinceRender` を下ろす (INV-47)。描画を待ってから書き換えることはしないので、確定の直後に `#editor` へ打ち込んだ文字は上書きされない。(2) `#editor` の `input` イベントで `_editorChangedSinceRender` を立てる。(3) `#editor` からの全体描画 ([Render] / `l` / `d`) は、開いている編集欄を同期的に確定してから行い (描画はキューに入れる)、未保存の確認は出さない (INV-45)。ただし `#editor` が空で本文が空でない場合は、確定より前に INV-56 の確認を出し、Cancel なら `#editor` を本文に戻して印を下ろすだけにする。システムが `#editor.value` を代入する場合の一つであり、(6) のガードはそのまま働く。`_editorChangedSinceRender` は、`#editor` の内容をモデルに取り込んだ時点で (同期。描画の完了は待たない) 下ろす。 また、システムが `#editor.value` を書き換えるとき (確定・Undo・挿入の `onModelChanged`、文書の作り直し (`.md` のドロップ、Reload、初期状態からのペーストと描画、空の文書の開始)、Clear、コードビューへの切り替え) にも同期的に下ろす (INV-45 の「最後の全体描画またはブロックの確定の後の `input`」の定義にそろえる)。その後の `#editor` の `input` は、描画中であっても印をもう一度立てる (裁定 T32)。(4) 編集モードでブロックの開始ジェスチャが行われたとき、`_editorChangedSinceRender` が立っていれば、先に `#editor` の内容で全体を描画し直す (INV-45)。 (5) ブロック編集欄を開いたまま `#editor` にフォーカスが入った場合 (Shift+Tab などのキーボード操作を含む) は、その `focusin` のハンドラの中で編集欄を同期的に確定する (`#editor` への入力が、後の確定による `#editor.value` の書き換えで失われないため。裁定 T19)。(6) ブラウザの Undo / Redo の履歴は、ページの中で 1 本である (Chromium では、ブロック編集欄の履歴が尽きた後の Ctrl+Z が、以前に入力した `#editor` に `historyUndo` として届き、フォーカスも `#editor` へ移る)。システムが `#editor.value` を代入すると、それより前の `#editor` の Undo の履歴は文書と対応しなくなる。そこで UIController は `#editor` の `beforeinput` で、`inputType` が `historyUndo` / `historyRedo` で、かつフォーカス (`document.activeElement`) が `#editor` でないものを `preventDefault()` する (`#editor` の中で押した Undo / Redo と、それ以外の入力は妨げない)。ブロック編集欄・パレット・本体での Ctrl+Z が、`#editor` と文書をずらすことはない (INV-45、INV-47、PRT-U36)。

```javascript
setViewMode(mode, metadata) {
  // Set body class: view-initial / view-markdown / view-code
  document.body.classList.remove("view-initial", "view-markdown", "view-code");
  document.body.classList.add(`view-${mode}`);

  const fileInfo = this.elements.fileInfo;
  const editor = this.elements.editor;
  const affordance = document.getElementById("affordanceText");

  switch (mode) {
    case "code":
      fileInfo.textContent = this._formatFileInfo(metadata);
      fileInfo.style.display = "block";
      editor.readOnly = true;
      editor.style.display = "none";
      if (affordance) affordance.style.display = "none";
      break;
    case "markdown":
      fileInfo.style.display = "none";
      editor.readOnly = false;
      editor.style.display = "";
      if (affordance) affordance.style.display = "none";
      break;
    case "initial":
      fileInfo.style.display = "none";
      editor.readOnly = false;
      editor.style.display = "";
      if (affordance) affordance.style.display = "block";
      break;
  }
}
```

**UIController.handleRender() メソッド (ボタンとキーボードの両方で使用):**

```javascript
async handleRender(theme) {
  if (this.orchestrator.isCodeViewActive()) {
    // Code view: CSS-only theme switch (no file re-read, no DOM rebuild)
    applyTheme(theme);
    this.state.setTheme(theme);
  } else if (!this.orchestrator.isPreRenderState()) {
    const content = this.preprocessInput(this.elements.editor.value);
    this.state.setMarkdownText(content);
    await this.orchestrator.reRender(theme);
    this.setViewMode("markdown");
    this.showKeyHint("markdown");
  } else {
    // Initial state: render if editor has content
    const content = this.preprocessInput(this.elements.editor.value);
    if (content.trim()) {
      await this.orchestrator.loadMarkdown(content, theme);
      this.setViewMode("markdown");
      this.showKeyHint("markdown");
    }
  }
}
```

**UIController.handleReload() メソッド (Reload ボタンと `r` キーで使用):**

```javascript
async handleReload() {
  if (this.orchestrator.isPreRenderState()) return;
  const theme = this.state.currentTheme;
  if (this.orchestrator.isCodeViewActive()) {
    const metadata = await this.orchestrator.reloadCodeView(theme);
    if (metadata) this.setViewMode("code", metadata);
  } else {
    const rawText = await this.orchestrator.readMarkdownFile();
    if (rawText === null) return; // toast already shown
    const text = this.preprocessInput(rawText);
    this.elements.editor.value = text;
    await this.orchestrator.loadMarkdown(text, theme);
    this.setViewMode("markdown");
    this.showKeyHint("markdown");
  }
}
```

**RendererOrchestrator ファサードメソッド (LOD準拠):**

```javascript
reRender(theme) {
  this.state.setTheme(theme);
  applyTheme(theme);
  this.renderAll();
}

async reloadCodeView(theme) {
  return await this.sourceFileRenderer.reload(theme);
}

async renderCodeView(file, fileHandle) {
  this._viewState = "code";
  applyTheme(CONFIG.codeView.defaultTheme);
  const metadata = await this.sourceFileRenderer.render(
    file, fileHandle, CONFIG.codeView.defaultTheme
  );
  return metadata;
}

// .md fileHandle storage for reload
_mdFileHandle = null;

async loadMarkdown(text, theme, fileHandle = undefined) {
  if (fileHandle !== undefined) this._mdFileHandle = fileHandle;
  this.state.setMarkdownText(text);
  this._viewState = "markdown";
  this.state.setTheme(theme);
  applyTheme(theme);
  await this.renderAll();
}

/**
 * Read .md file from stored fileHandle. Returns raw text or null.
 * Shows appropriate toast when unavailable:
 *   - FILE_SYSTEM_HANDLE_SUPPORTED && no handle -> "No file to reload..."
 *   - !FILE_SYSTEM_HANDLE_SUPPORTED           -> "Chrome/Edge 86+ required"
 */
async readMarkdownFile() {
  if (!this._mdFileHandle) {
    const msg = FILE_SYSTEM_HANDLE_SUPPORTED
      ? CONFIG.codeView.reloadNoFileMsg
      : CONFIG.codeView.reloadUnavailableMsg;
    showToast(msg, CONFIG.codeView.toastDurationMs);
    return null;
  }
  const file = await this._mdFileHandle.getFile();
  return await file.text();
}
```

注意: `renderCodeView()` は `preview.classList` 操作を行わない。body クラスの管理は UIController.setViewMode() に委譲される。

UIController は RendererOrchestrator のパブリックメソッドのみを呼び出し、内部の SourceFileRenderer に直接アクセスしない。

`_mdFileHandle` は RendererOrchestrator (UseCase層) が保持する。Adapter用Interfaceは不要（ScrollMementoと同じCA意図的逸脱）。

**(その場編集。2026-xx-xx 追記)** `[Render]` / `l` / `d` の経路の判定は、純粋関数 `renderRouteFor(isCodeView, isPreRender)` に切り出す。`"theme"` (コードビュー: CSS の切り替えだけ)、`"editorIntoDocument"` (Markdown 表示中: 同じ文書。開いている編集欄を確定してから、改行の正規化だけを行って全体を描画する。裁定 T33)、`"newDocument"` (初期状態: 改行の正規化 → ラッパーの除去 → 新しい文書) の 3 つ。

### 5.10.1 Touch Paste Assist (FS-16)

プレレンダー状態で `#preview` 領域をクリック/タップすると `#editor` にフォーカスを移動する。
UIController.setupTouchPasteAssist() で設定する。

```javascript
setupTouchPasteAssist() {
  const preview = this.elements.preview;
  const editor = this.elements.editor;

  preview.addEventListener("click", (e) => {
    if (!this.orchestrator.isPreRenderState()) return;
    if (editor.value.trim() !== "") return;
    editor.focus();
  });
}
```

**iOS Safari 対策:**
- アフォーダンステキストの後に空白行（`" \n"` x 50行）を `textContent` に付加する。iOS Safari はレンダリングされたコンテンツのない領域で click を発火しないため、プレビュー領域全体を「描画済み」にする必要がある。
- `#affordanceText` の CSS は `padding-top: 40px` で上部寄せ。`white-space: pre` により空白行がそのまま高さとして描画される。
- `#preview` に `background-color` を明示的に指定する (`#fff` / dark: `#222`)。安全マージンとして維持。
- `<meta name="viewport">` は追加しない。追加すると iPhone の既存レイアウトが崩壊するため。

**設計判断:**
- `click` イベントのみ使用する。`touchstart` は使用しない
- `click` は iOS Safari でもユーザージェスチャとして認識され `focus()` が成功する (PoC v4 で iPad 実機検証済み)
- `click` はピンチ・スクロールジェスチャでは発火しないため、ピンチアウト操作を阻害しない。`touchstart` + `preventDefault()` 方式ではピンチの1本目の指で `focus()` が発火しキーボードが出るため、ピンチ操作が不可能になる問題があった
- 条件チェック (`isPreRenderState()` + editor空) により、レンダリング済み状態では無干渉

### 5.13 AI出力前処理 (preprocessInput)

UIController.preprocessInput() は、AIツールが出力する外側のMarkdownフェンス (ラッパー) を除去する。処理は純粋関数 `splitMarkdownWrapper(text)` (新設の `src/js/textTransforms.js`、`@purity pure`。DOM と CONFIG に依存しない純粋な文字列関数だけを置くファイルで、5.14.1 の改行コードと BOM の変換関数も置く。R7.9。裁定 T8) に委ね、`body` を返す。

**`splitMarkdownWrapper(text)` は `{ prefix, body, suffix }` を返す:**

入力は LF に正規化済みの文字列とする (すべての経路で「改行の正規化 → split」の順。5.14.1)。

1. 先頭の空行 (空白だけの行を含む) に続いて、3 個以上のバッククォート、`markdown` (大文字小文字を区別しない)、任意の空白、改行、が並ぶ部分を `prefix` の候補とする (現行コードの `markdown\s*\n` と同じ範囲)。
2. 末尾にある「改行 + 候補と **同じ数** のバッククォート + 任意の空白と改行」を `suffix` の候補とする。
3. **両方の候補が揃った場合だけ** 除去する (`prefix` と `suffix` に入れる)。片方しか無い場合は何も除去しない (`markdown` 言語の例のコードブロックで始まる普通の文書や、コードブロックで終わる普通の文書を壊さないため)。
4. `prefix + body + suffix === text` が常に成り立つ (除去したものをすべて正確に返す)。`trim` はしない。

**現行からの動作の変化:** (a) ラッパーが無いのにコードブロックで終わる文書の閉じフェンスを除去しなくなる (不具合の修正)。(b) 閉じフェンスの無い (途中で切れた) AI 出力は除去しなくなる (先頭のフェンスが残り、全体がコードブロックとして表示される。両端が揃うことを要件とした旧 5.13 と同じ動作)。 **残る限界:** `markdown` 言語の例のコードブロックで始まり、普通のコードブロックで終わる文書は、両端が揃って見えるので除去される (表示が崩れるが、保存では `prefix` と `suffix` を戻すので内容は失われない。現行のコードと旧 5.13 も同じ動作)。「先頭のフェンスが末尾より前で閉じていれば除去しない」という条件は、外側と内側に同じ数のバッククォートを使った AI 出力 (よくある形) の除去を止めてしまうので採らない。

- ネストされた内部のコードブロックは除去しない。
- `.md` の読み込み (D&D と Reload)、初期状態からの Ctrl+V のペースト、初期状態の `#editor` からの描画で適用する (INV-17)。Markdown 表示中の `#editor` からの描画と、保存のときの `#editor` の取り込みでは適用しない (改行の正規化だけ。5.14.1、INV-33)。
- 保存時は、記録した `prefix` と `suffix` を付け直す (INV-38)。

### 5.14 Markdown その場編集

#### 5.14.1 読み込みと保存の変換 (純粋関数)

読み込み (ファイル): バイト列 → BOM の検出 (先頭 3 バイトが `EF BB BF`) → デコード (`File.text()`。BOM は除かれる) → 改行コードの記録と正規化 (CRLF と単独の CR を LF に。INV-44) → `splitMarkdownWrapper` (5.13) → 本文 → モデル。初期状態からのペーストと `#editor` からの描画も、同じく「改行の正規化 → `splitMarkdownWrapper`」の順とする (ペーストした文書の改行コードは LF として扱う)。**Markdown 表示中の `#editor` からの描画と、保存のときの取り込み (`applyEditorText`) では、改行の正規化だけを行い、`splitMarkdownWrapper` をかけない** (`#editor` には既にラッパーを除いた本文が入っているので、もう一度除くと、`markdown` の例で始まりコードブロックで終わる本文の両端のフェンスを失う。main の `handleRender` は Markdown 表示中も `preprocessInput` を通すので、動作の変更になる。利用者から見ると、Markdown 表示中に `#editor` の中身をラッパー付きの AI 出力に貼り替えて [Render] すると、ラッパーは除去されず、全体が 1 つのコードブロックとして表示される。ラッパーを除くには、Clear してからペーストする (PRT-W23)。裁定 T33)。保存はその逆順: 本文 → `prefix + body + suffix` → 記録した改行コードへ変換 → BOM を付ける → 書き込み。`DocumentSession.toFileText(bodyText)` がこの逆変換を行う。

関数は `textTransforms.js` の `detectLineEnding` / `normalizeLineEndings` / `convertLineEndings` / `hasUtf8Bom` (5.13 の `splitMarkdownWrapper` と同じファイル。すべて `@purity pure`)。初期状態からのペーストと描画では、ラッパーを除いた本文を `#editor` にも書き戻す (書き戻さないと、後の Markdown 表示中の描画で T33 により除去されず、`#editor` とモデルがずれる)。空白だけのペーストは横取りしない (ブラウザの既定の動作に任せる)。

#### 5.14.2 ブロックモデル (`MarkdownBlockModel`, `@purity pure`)

- `fromBody(bodyText, lexer)`: 最上位トークンからブロックの列を作る。開始タグが閉じていない `html` トークンは、タグが閉じるまでの後続トークンと合わせる (INV-41。タグの釣り合いは `html` トークンの中の非 void 要素の開始タグと終了タグを数えて判定する)。`space` トークンは直前のブロックの `separatorAfter` に入れる (先頭の `space` は先頭の空ブロックの区切りとして保持する)。
- 不変条件: `toBody() === 全ブロックの (raw + separatorAfter) の連結` (INV-41)。
- 原文との突き合わせ: marked は、ラベルが既に定義された参照リンク定義 (大文字小文字を区別しない) をトークンに積まずに読み飛ばし、その後の改行を直前のトークンの `raw` に足す [検証済: marked 18.1.0]。そこで `fromBody` / `withBody` は、本文全体を 1 回字句解析し、各トークンの `raw` を本文の該当位置と突き合わせる (`raw` の末尾の、本文に無い改行は除く)。一致しない位置 (読み飛ばされた定義の区間) では、その位置から次の空行まで (定義のタイトルは空行を含まないので、定義はそこで終わる) の短い区間だけをそれだけで字句解析し、先頭のトークンが `def` (または空行) なら、それを 1 つのトークンとして補い、元のトークン列の突き合わせを区間の後ろから続ける。読み飛ばされた定義は、1 つずつ独立した `def` ブロックになる (marked が定義 1 つにトークン 1 つを作るのと同じ単位にし、編集欄で 1 つずつ開けるようにするため)。区間が空行までに 4,096 文字を超える場合と、先頭のトークンが `def` でも空行でもない場合は、その位置から後ろの本文全体を改めて字句解析して続ける (まれな場合だけ)。字句解析する文字数は、重複の数によらずほぼ本文 1 回分である (INV-51)。`links` は、本文全体を 1 回で解析した場合と同じく、先に出た定義を優先する。`links` の各項目は `{href, title}` の凍結した写しとし、marked のオブジェクトを共有しない。
- 退避: それでもブロックの連結が本文と一致しない場合と、字句解析が例外を投げた場合は、本文全体を 1 つのブロック (種類 `document`) とし、`isWholeDocument` を真にする (本文を書き換えない)。そのブロックの描画は、ブロック単位の描画と同じ経路で行い、解析の例外は従来どおり `Markdown Parse Error` として表示する。モデルが 1 ブロックの扱いに変わったとき、RendererOrchestrator は `console.error` に記録し、`ModelChangedPort.onBlockSplitFailed()` を呼ぶ (UIController がトーストを出す)。空の本文は退避ではない (ブロック 0 個)。
- ブロック ID: `fromBody(bodyText, lexer, firstBlockId)` は `firstBlockId` から振る (新しい文書では、RendererOrchestrator が持つアプリ全体のカウンタ `_nextBlockId` の値を渡す。起動時は 1。ID はアプリ全体で単調に増え、文書をまたいでも、Clear やコードビューの後でも再利用しない。INV-48)。`withBody` / `replaceBlock` / `insertAfter` は新しい本文を字句解析し、`BlockDiff.diffBlocks` で前の列と対応付け、対応したブロックは ID を引き継ぎ、それ以外には `nextBlockId` から新しい ID を振る。自身は変更せず、`ModelChange` (新しいモデルと、本文が変わったかどうか) を返す (R7.5)。
- `diffBlocks(oldBlocks, newBlocks, maxCells)` (`@purity pure`): (1) 先頭から原文の一致するブロックを除く。(2) 末尾から同様に除く。(3) 残った区間の大きさが k × m のとき、k·m が `maxCells` (`CONFIG.edit.diffMaxCells`) 以下なら、その区間だけを LCS で対応付ける。超える場合は、区間のブロックをすべて新しいブロックとして扱う。計算量は O(n + k·m) で、k·m は上限で抑えられる。1 回の確定で変わるブロックは通常 1〜数個なので、k と m は小さい。1 MB の文書 (約 9,300 ブロック) でも、(1) と (2) は線形の比較で済む。
- 末尾の改行: トークンの種類によって `raw` が末尾の改行を含むかが異なる [検証済]。編集欄に表示するときは末尾の改行を除き、確定時に付け直す。

#### 5.14.3 部分再描画 (`RendererOrchestrator.commitBlock`)

同期の部分 (操作のイベントハンドラの中、最初の `await` より前):

1. 対象ブロックの要素で `ScrollMemento.captureAnchor` を取る (上端の画面上の位置。INV-46)。
2. `replaceBlock` で `ModelChange` (新しいモデル、`isChanged`、新しいモデルでの基準のブロック ID `anchorBlockId`) を作る。`isChanged` が偽 (原文が変わらない) なら、ここで終える (モデル・DOM・Undo の記録・未保存の印を変えない。INV-48)。
3. 前の現在のモデルを `_previousModel` (Undo の記録、1 件) に入れ、新しいモデルを現在のモデルにする。
4. `onModelChanged` を呼ぶ (UIController が `#editor.value` と未保存の印を更新する)。
5. 描画をキューに入れる。

非同期の部分 (描画のキューの中。INV-47):

6. `MarkdownRenderer.replaceBlocks(_renderedModel, _currentModel, heldBlockId)`: ブロック ID で対応付け、原文と参照リンク定義の署名が同じブロックは DOM をそのまま残す。ブロック編集欄が開いているブロック (`holdBlock`) は、HTML が変わっても外枠を残し、古い描画として記録する。編集欄が閉じたとき (`releaseBlock`) に古い描画なら、そのブロックだけを部分描画し直す (INV-47)。HTML が変わったブロックと新しいブロックだけ `wrapper.innerHTML = sanitize(html)` で作り直す。消えたブロックの要素は外す。sanitize 後の文字列を連結してもう一度パースすることはしない。キャッシュから、現在のモデルに無いキーを捨てる。
7. 差し替えた要素に対して hljs → `ExternalImageGate.apply(root)` → Mermaid → PlantUML (`mode: "placeholder"`) を行う。
8. 差し替えの直後と、DOM の安定後 (`waitForDOMStability`) に `restoreAnchor` を行う (基準の要素は `anchorBlockId` で探す。まとまった描画では最後の要求のアンカーを使う)。`_renderedModel` を、この描画で使った現在のモデルにする。

計測の目印 (PRT-U25): `commitBlock` の同期の部分の始めに `performance.mark("grsmd-commit-start")` を置き (直前の同名の mark を消してから)、その確定を含む部分描画の `replaceBlocks` の直後に `performance.measure("grsmd-commit", "grsmd-commit-start")` を作る (直前の同名の measure を消してから作り、作った後で mark を消す。最後の 1 件だけが残る)。原文の変わらない確定では mark を消す。どちらも通信も保存もしない。

複数の確定がキューに溜まった場合も、各描画は「最後に描画したモデル」から「その時点の現在のモデル」へ更新するので、中間のモデルを描画する必要はない。参照リンクの定義が変わった場合は署名が変わるので、全ブロックの HTML を作り直して比べる (変わったものだけ差し替える。この場合は INV-51 の 300 ms の対象外とする)。

文書が作り直された場合 (`DocumentSession.documentId` が変わった場合) は、キューの中の、それより前の部分描画とアンカーを捨て、新しい文書の全体描画だけを行う (INV-47)。文書が無くなった場合 (Clear、コードビュー) も、キューの中の部分描画とアンカーを捨てる (全体描画は行わない)。ブロック ID は文書をまたいで再利用しないので、描画の待ちの間に画面に残った古い文書の要素の ID は、新しいモデルに存在せず、クリックしても開かない (INV-29)。

#### 5.14.4 全体描画 (`renderAll`) の変更

全体描画 (初回、ドロップ、Reload、`l` / `d`、`#editor` からの描画) でも、ブロックごとに `.md-block` を作って描画する。生 HTML のまとめ (INV-41) によって、`<details>` などの表示は従来の `marked.parse` と同じになる。PlantUML は従来どおり `mode: "consent"` で描画する。全体描画では HTML のキャッシュと Undo の記録を空にする。全体描画も、キューに入れた時点の描画の世代を持ち、実行の時点で世代が進んでいれば何もしない (続けて入った全体描画は最後の 1 回だけが描き、PlantUML の確認も 1 回だけ出る)。空の文書 (ブロックが 0 個) では、ID を持たない空のブロック (`.md-block.md-block-empty`) を 1 つ置く (INV-49)。編集モードでそれを開いた編集欄の確定は、本文が空白だけでなければ `insertAfter(null, text)` で入れ、空白だけなら何もしない。

#### 5.14.5 テキスト操作 (`MarkdownTextOps`, `@purity pure`)

CONFIG を読まず、必要な値は引数で受け取る。`toggleWrap` (選択が空なら変更しない)、`insertTableRow` / `insertTableColumn` (列はバックスラッシュの付かない縦棒だけで区切る。コードスパンの中の縦棒も区切りとして数える。区切り行にも区切りのセルを足し、配置指定は既定とする)、`insertBlockText` (前後に空行が無ければ補って挿入する。INV-52)、`insertTextAt` (`<br>` の挿入に使う)、`changedRange(before, after)` (2 つの文字列の共通の先頭と末尾を除いた、置き換える 1 つの区間 `{start, end, text}`。5.14.6 の Undo の対象にする挿入に使う)。

#### 5.14.6 編集の開始ジェスチャと「外側」(BlockEditController)

- 開始ジェスチャ (INV-29): 編集モードの間に、プレビュー内で主ボタンの `pointerdown` から `pointerup` までの移動が `CONFIG.pan.activationThresholdPx` 以下で、`pointerup` の時点で `window.getSelection()` が空で、対象が INV-29 の除外対象の内側でない場合 (除外対象の列挙は INV-29 だけに置く)。ブロック ID は `pointerdown` の時点で取る (INV-29)。
- 外側 (INV-30): ブロック編集欄、編集パレット、ポップオーバー以外の要素 (上部バー、スクロールバー以外のプレビュー、モーダル、トーストを含む)。マウスでは `pointerdown` で、タッチとペン (`pointerType !== "mouse"`) では移動が閾値以下の `pointerup` で確定する (指でのスクロールでは確定しない)。
- 確定 (11-c の `commitBlock`) は同期でモデルを更新する (描画の完了は待たない。INV-47)。確定・取消は `dispatch` で表を通してだけ行う (表の外で状態を変える入口は持たない)。
- `#editor` の `focusin` は UIController が受け (`#editor` を持つのは UIController)、ブロック編集中なら `BlockEditController.dispatch("editorFocused")` で確定する (5.7 (5)、INV-30)。
- Tab: 編集欄の `keydown` で Tab (Shift なし、IME の変換中を除く) を受けたら `preventDefault()` し、パレットの現在のボタンへフォーカスを移す (INV-53)。
- `getSelectionRange()` / `applyTextEdit(edit)` で選択範囲と文字列だけを受け渡し、編集欄の要素は外へ渡さない (LoD)。
- 編集欄の Undo の対象 (INV-52、OS-18): `applyTextEdit` (パレットの書式・挿入) と表の中の Enter (`<br>`) は、`MarkdownTextOps.changedRange` で変わる区間だけを `setSelectionRange` で選び、`document.execCommand("insertText", false, text)` で入れる (ブラウザの編集欄の Undo の履歴に載る。非推奨の API だが代わりが無い)。`execCommand` が無い、`false` を返す、例外を投げる、または入れた結果が求める文字列と違う場合は、`value` の代入にフォールバックする (その場合はその変更を Ctrl+Z で戻せない)。その後で選択範囲を `edit` のとおりにする。
- IME: `compositionstart` から `compositionend` までと、`event.isComposing` が真、または `keyCode === 229` の `keydown` は処理しない (INV-27 / INV-28)。

- 編集欄は外枠 (`.md-block`) の中に置き、外枠の元の子要素は退避して、閉じるときに戻す (外枠は残るので、ブロックの特定は変わらない)。編集中の外枠には `.md-block-editing` を付ける。`font-family: monospace` と `overflow-y: hidden` は CSSOM で設定し、高さは `scrollHeight` に枠の幅を足した値にする (CSS は `box-sizing: border-box`、`width: 100%`。INV-40)。
- INV-29 の除外対象の「入力要素」は `input`、`textarea`、`select` とする。編集中のブロックの外枠そのものの上の押下は、編集欄の内側として扱う。
- スクロールバーの判定: 押下の対象が `#preview` または `document.documentElement` で、`offsetX > clientWidth` または `offsetY > clientHeight` のとき、スクロールバーの上とみなす (外側としない。INV-30)。
- `pointerType` が `"mouse"` 以外 (空文字を含む) の押下は、タッチとペンの扱いにする。
- ダブルタップ (INV-31) は、タッチの `pointerup` の時刻 (単調時計の `performance.now()`。壁時計の `Date.now()` は使わない) と座標で判定する (`BlockEditController.isDoubleTap`)。ダブルクリックは `dblclick` の事象で判定する。

#### 5.14.7 保存 (`SaveDocument` / `SaveDocumentAs`、UseCase 層)

- 押下のハンドラの中で同期的に、(`#editor` を取り込む場合は先に INV-56 の確認を出し、Cancel なら `#editor` を本文に戻して、何も始めずに終える) `MarkdownFileAccess.startPermissionRequest(location.fileHandle)` (Save) または `startSavePicker(location.fileName)` (Save as) を始め、続けて開いている編集欄を確定し、`#editor` に未描画の変更があればそれをモデルに取り込む (`applyEditorText`。どちらも同期。INV-33)。その後で `SaveRequest` (セッション、保存先、本文、権限またはダイアログの Promise、`confirmOverwrite` ポート) を組み立てて `execute` に渡す。アクティベーションが失効していた場合 (`SecurityError` 等) は `failed` とし、`saveActivationLost` のトーストを出す (INV-25)。
- SaveDocument は UI を直接扱わない。外部変更の確認は、`SaveRequest.confirmer` (UIController が実装する `OverwriteConfirmPort`) の `confirmOverwrite()` (`Promise<boolean>` を返す) を通して行う (INV-39)。
- Save: 保存先 (`location.fileHandle`) が無い、または書き込み API が無い場合は Save as と同じ動作にする。権限 → `readLastModified` (`NotFoundError` は `failed`) → 基準と異なれば `confirmOverwrite` → `toFileText` → `writeFile` → `withSaved`。
- Save as: 保存ダイアログで得た handle と名前で、新しい `DocumentLocation` を返す (以後の Save と Reload の対象)。書き込み API が無い場合は `startDownload` で Blob (`text/markdown;charset=utf-8`) をダウンロードし、`downloadStarted` を返す。ダウンロードでは保存先も基準も変えない (INV-26)。Blob URL は `<a>` の click の後のタスクで `URL.revokeObjectURL` する。ダウンロードは、押下のハンドラの中で、確定 (同期) に続けて同期的に始める (INV-33。ユーザーアクティベーションの中で始まる)。それでも止められた場合 **[一般知識・未検証: iOS Safari など]** は、INV-26 により基準は変わらず、安全側に倒れる (PRT-W06 を iOS Safari でも行う)。
- `SaveOutcome` は保存を始めたときの `documentId` を持ち、UIController は現在の文書 ID と一致するときだけ反映する (INV-54)。保存中 (`writingFile`) は、文書の置き換えを拒む (INV-54)。
- 書き込みの可否は `FILE_SYSTEM_WRITE_SUPPORTED` (`typeof window.showSaveFilePicker === "function"` 等) で判定する **[要検証: 判定式]**。`FILE_SYSTEM_HANDLE_SUPPORTED` とは別にする。
- 5 MB (CON-08) を超えた文書も保存できる (読み込みの上限は変えない)。
- 保存先は `DocumentLocation` だけを正とする (`RendererOrchestrator._mdFileHandle` は廃止。INV-55)。`DocumentSession` は fileHandle を持たない。

- 保存先が無い Save は、仮の保存先 `DocumentLocation(defaultFileName, null)` で、保存ダイアログを使う Save as と同じに動く。書き込み API が無い場合は、権限の要求もダイアログも始めず (`permissionOrPicker` は無し)、ダウンロードにする。
- use case が想定外の例外を投げた場合は、`failed` (`saveFailed`) として扱う (未保存のまま)。
- `MarkdownFileAccess.writeFile`: `write()` または `close()` が失敗したら `abort()` してから元のエラーを投げる (`abort()` 自体の失敗は無視し、元のエラーを隠さない)。書き込みと `close()` が成功した後の `lastModified` の読み直しが失敗した場合は、エラーではなく `null` を返す (保存は成功で、`saved` とする)。そのとき `DocumentSession.withSaved` は基準の `lastModified` を「不明」(`LAST_MODIFIED_UNKNOWN`。`DocumentSession.js` が公開する専用の値で、`null` (ファイルに由来しない文書) とも、どの更新日時とも等しくない) として記録する。`SaveDocument` は、基準が不明なら、ファイルの更新日時によらず必ず INV-39 の確認を出す。基準が `null` の文書 (ペースト・空の文書) を Save as で初めて保存した場合も同じである。次の保存が成功して更新日時を読めれば、基準は改めて記録される。

#### 5.14.8 未保存の判定とタブのタイトル

`_isDocumentDirty()` は導出値 (3.3 の 11-e)。真の間は `document.title` を `CONFIG.edit.titleUnsavedPrefix + 元のタイトル` にし、偽になったら元に戻す (ファイル名は入れない。INV-50)。`beforeunload` のハンドラは起動時に 1 度だけ登録し、`_isDocumentDirty()` が真のときだけ `event.preventDefault()` を呼ぶ (INV-22)。

パレットの状態表示 (`paletteStatus`) は、セッションが無ければ空とし、保存先が無ければ名前に `CONFIG.edit.defaultFileName` を使う。

**既知の制約 (bfcache):** `beforeunload` のリスナーは起動時から常に登録されている。Firefox などは、このリスナーがあるページを bfcache (戻る・進むのキャッシュ) に入れないので、戻る・進むでページが読み込み直されることがある。未保存でない間だけリスナーを外す方式は採らない。

#### 5.14.9 Undo (INV-48)

`_previousModel` に、直前 1 回の「本文を変えた確定」または「編集中でないときの挿入」の前のモデルを持つ。Undo は、同期で基準のアンカー (戻す範囲の最初のブロックの上端。その要素がまだ描画されていない場合は、DOM に残っている対応する位置の要素 (確定前のブロックの要素) の上端。どちらも無ければアンカーを取らず、補正しない) を取り、`_previousModel` に現在の `nextBlockId` を引き継いだモデルを現在のモデルにして (ID を再利用しない。INV-48) `_previousModel` を空にし、`anchorBlockId` を戻した範囲の最初のブロックとし (戻した結果、文書が空なら `anchorBlockId` は無しとし、補正しない。INV-49)、`onModelChanged` を呼び、描画をキューに入れる (5.14.3 の手順 6〜8)。Redo は無い (OS-18)。原文の変わらない確定と、編集中の挿入 (編集欄の文字列の変更) は、記録を変えない。

#### 5.14.10 CSP との整合 (INV-20)

インラインのイベントハンドラ属性は使わない。パレットのアイコンはインライン SVG (DOM 生成) とし、外部の画像を読まない。`blob:` のダウンロードが CSP の下で動くことを PRT-W06 で確認する。

#### 5.15.5 有効・無効

| ボタン | 有効になる条件 |
| --- | --- |
| Bold / Italic | ブロック編集中で、選択範囲がある |
| Undo | ブロック編集中でなく、Undo の記録がある (INV-48) |
| Insert row / Insert column | 表のブロックを編集中 |
| Insert table / Mermaid | 常に有効 (挿入位置は INV-52) |

ボタンの有効・無効は、未保存の印を更新するたびと、編集欄の選択範囲が変わるたび (document の `selectionchange` を capture で受ける) に更新する。編集中の挿入 (Insert table / Mermaid の雛形) は、カーソル位置 (選択の終わり) に入れる。Bold / Italic は、選択が空なら何もしない。

#### 5.15.6 キーボード操作とタブ順

INV-53 のとおり。パレット (`role="toolbar"`) は `body` の直下に置き、プレビューの中へは移さない (確定でブロックの要素が外れても影響を受けず、プレビューに委譲されたリスナーもパレットの操作を受け取らない)。ロービングタブインデックス (ツールバーの中で 1 つのボタンだけが `tabindex="0"`) とし、編集欄からは Tab の自前の処理で移る。パレットの内側にフォーカスがある間は、document の文字のショートカットを無効にする (INV-14)。`@media print` でパレット・ポップオーバー・不可視ブロックの帯を隠す。

ポップオーバーの中では、上下左右の矢印で 4 つのボタンを巡回し、Enter / Space で実行する (実行の後はポップオーバーを閉じ、フォーカスは Mermaid のボタンへ戻る)。ポップオーバーの Esc はポップオーバーを閉じ、Mermaid のボタンへフォーカスを戻す。パレットの Mermaid のボタンで Enter / Space を押すと、ポップオーバーを開き、先頭のボタンへフォーカスを移す。パレット上の Esc は、ポップオーバーが開いていれば閉じてから、INV-53 の動作をする。

#### 5.15.7 資源の生存期間

パレットの `pointermove` / `pointerup` / `resize` のリスナーは `show()` で登録し、`hide()` で外す。ブロック編集欄のリスナーは編集欄を開いたときに登録し、閉じたときに外す。Clear とコードビューへの切り替えではパレットを閉じる (11-c)。

#### 5.16.2 `@purity` の検査 (CON-15)

数える対象: クラスのメソッド (コンストラクタ、getter、setter を含む)、`function` 宣言と関数式、本体が `{ }` のブロックであるアロー関数。数えない対象: テストコード、自動生成コード、ベンダリングコード、本体が単一の式のアロー関数。検査: Node の小さなスクリプト (新しい依存を使わない) で、対象の関数の直前の JSDoc に `@purity` がちょうど 1 つあることを数え、付与率を出力する。スクリプトの置き場は実装時に決める。付与率は 100% でなければならない。
